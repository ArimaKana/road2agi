# Road to AGI

完整流程的浏览器游戏：四个大区 28 间房、十二种敌人和四类精英、四个 Boss、九张召唤卡、无尽试炼。DeepSeek 是生成的八向二维主角，敌人和 Boss 是两向或四向的生成动画，大招里的梁文锋是一张法象图和一只巨拳，房间和机关是低模 3D。

技术栈：Vite、Vue 3、TypeScript、Three.js 0.187。优先使用 WebGPU，浏览器不支持时 Three.js 自动回退到 WebGL 2，地址加 `?webgl` 可强制回退。

## 启动

需要 Node.js 22.18 或以上。

```sh
npm install
npm run dev
```

打开 http://localhost:4173 。

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 开发服务器 |
| `npm run build` | 类型检查后构建到 `dist/`，可直接托管到任意目录 |
| `npm run preview` | 预览构建结果 |
| `npm test` | 战斗模拟、房间、机关、输入、存储和特效的自动测试 |
| `npm run test:browser` | 独立无头浏览器中的启动、输入与渲染回归测试 |
| `npm run typecheck` | 只做类型检查 |

浏览器测试需要 Chrome、Chromium 或 Edge；脚本会查找常见安装位置，也可通过 `CHROME_PATH` 指定可执行文件。测试使用临时用户目录和仅本机可访问的开发服务器，结束后自动清理。

## 哔哩哔哩 Toy

接入 [Toy JS SDK](https://www.bilibili.com/toy/publish/sdk)，在 Toy 页面或其沙箱中按需载入官方 SDK；本地开发和独立站点继续正常游玩。存档、解锁、设置和试炼最远纪录仍保存在浏览器本地，不使用云存储或共享存档。

试炼模式使用榜位 **1** 的总榜，分数为本局到达的房间数，同分先到者在前。点击首页「试炼模式」或试炼结算页的「排行榜」按钮，在独立弹窗中查看前 50 名和自己的排名；关闭按钮、弹窗外区域、Esc 或手柄 B 可关闭。打开弹窗才读取，读取后缓存，可手动刷新；每局结算时提交一次，失败时保留本地纪录并可手动重试。未登录玩家可以看榜，提交前由平台处理登录及用户数据确认。Toy 预览环境若不支持写入，显示提示并跳过提交。

开启过无敌模式、全卡解锁或觉醒调试参数的试炼不参与排名；恢复试炼会保留这项标记。这里只排除游戏内的调试功能，成绩由客户端上报。请求遇到 `307044` 限流时最多退避重试两次，不轮询榜单，不逐房间提交。

按**游戏区域的实际宽高**判断横屏：宽大于高时直接可玩，无需系统全屏或 Toy 沉浸模式，适用于普通窗口和嵌入预览。竖屏或方形区域显示覆盖整个页面的阻挡提示，暂停游戏并拦截背后的菜单、键鼠和手柄操作。B 站 App 内点击按钮请求 `setContainerMode({ orientation: 'landscape', immersive: true })`；普通浏览器尝试系统方向锁定（部分浏览器需先进入全屏），失败时可手动旋转或调整窗口。实际区域变为横屏后遮罩自动消失，战斗需从暂停菜单手动继续；仅退出全屏不会阻挡横屏游玩。

战斗时右下角始终显示闪避、攻击和金色拳头大招按钮；键鼠和手柄模式下，各按钮右上角显示当前绑定的按键，改键后同步更新。闪避充能显示在左上 HUD 上。移动摇杆在触屏上自动显示，也可以在设置里常开。快速点击会保留按下与松开的记录；闪避和技能输入缓存 0.3 秒（顿帧中按的也算），普攻衔接会保留到当前攻击允许接下一段。连按打出连段；按住超过 0.4 秒进入蓄力，松手释放，蓄满 0.8 秒自动释放；继续按住会在收招后再次蓄力，Token 不足时改为连续轻击，松开停止。手机横屏更适合战斗。音乐与音效默认开启，首次点击、轻触或按键后播放。点右上角音符可选择“全部开启”“关闭 BGM”（保留战斗音效）或“关闭所有声音”，当前选择有勾选标记；设置里的“声音”也可切换这三种模式，刷新后保留选择。BGM 使用项目里的《当然可以好问题》，循环播放；切换房间、重开与返回首页时接着播放，页面进入后台时暂停，回到前台后继续。

## 后门：跳到任意房间

开发和试玩用，不属于游戏内容，所有构建里都能用。

- 按 `` ` ``（数字 1 左边的键）打开房间列表，点一间就进去。任何时候都能按，战斗会先停下；再按一次或按 Esc 关闭并接着打。
- 地址加 `?room=2-5`，打开页面就直接进那间房，死了或通关后“再来一局”也从那里开始，改完地图刷新就能看到。手机没有这个键，用这个办法。
- 跳过去等于从那间房开始新的一局：生命、觉醒、Token 回到开局值，击杀和用时清零。写错房间号就从 1-1 开始。
- 按 F8 或地址加 `?god` 打开无敌模式：不受伤害，Token 一直满。HUD 上会显示“无敌”，再按一次 F8 关闭，开着时刷新页面也不会关。
- 地址加 `?unlock=all`，这次打开时九张卡都能选，开局选三张，也能直接带 Claude，不写存档。加 `?unlock=reset` 清掉解锁存档，回到首局状态。

## 已实现

- 四个大区共 28 间房（`src/game/level.ts`，用文字画的地图，可以直接改）：缓存废港、镜像书库、梯度熔炉各 9 间，第 1 至 3、5 至 7 间是战斗房，第 4 间事件房，第 8 间商店房，第 9 间 Boss 房，最后是零域的 4-1。每个大区一套配色。相机角度固定，跟随主角。
- 每间房一扇入口门、一扇出口门。主角进房后入口门关闭，清完全部波次出口门才打开，走进去就淡出到下一间；生命、觉醒和闪避充能带过去，不自动恢复。Boss 房的出口门通向整备点，出发后进下一大区的第一间，打赢 4-1 通关，中途死亡从 1-1 重来。
- 岔路：通向下一间战斗房的门分两半，走一半是补给路（敌人照常，奖励是补给），走另一半是险路（每波多一个最弱的敌人，奖励是强化和伙伴）。地图和 Boss 顺序不变。
- 十种机关，敌我同伤，清房后停止，规则和数值见设定文档第 7 节。缓存废港：压缩板（定时预警后砸下）、传送带（带走站在上面的单位，Boss 除外）、泄压阀（刺中后沿直线喷发，有冷却）。镜像书库：滑动书架（沿轨道平移，推开并弄伤碰到的单位）、折射镜（弩孔定时放出穿透弹，碰到镜面折射，刺一下换一边）。梯度熔炉：热浪喷口（一圈带缺口的热浪）、压印机（沿轨道连砸三下，最后一下慢半拍）。零域：格式化扫描线（扫过全房，留一条缺口）、删除区块（闪烁后消失，站在上面持续受伤）、冗余信标（刺一下恢复最近的区块）。事件房和商店房的地台是占位，分别回 30 生命和回满生命、觉醒。
- 暂停时画面切换为当前大区的线框关卡地图：固定等距视角，鼠标拖动平移、滚轮缩放（手机单指拖动、双指缩放，WASD 和手柄右摇杆也能平移）。每间房是一个线框盒，门与门用走廊线相连，圆点标出主角位置。走过的、当前的和门已打开的房间显示名称和类型，其余只显示编号和“未解锁”，当前房间的机关写明用法。
- 墙和缓存箱有碰撞：主角和敌人贴着滑动，攻击和软锁都穿不过去。敌人看得见主角时直奔过去，看不见时绕开障碍寻路。
- 朝向等级：主角八向，精英四向（选最接近的斜向），Boss 和小怪左右两向，过拟合圣像固定朝镜头。每个方向都单独生成，没有用镜像替代。
- 跑动和待机转身时经过中间方向，攻击、闪避和施法立即转向。朝向按设定文档第 2 节：跑动时朝移动方向，静止时保持原朝向，出招和蓄力转向瞄准方向；两个方向的分界处保留上一朝向，有约 8° 的迟滞。
- 瞄准与锁定：鼠标、右摇杆或触屏拖动指定的方向保持不变，鼠标指向的敌人优先选中；不手动瞄准时，在移动方向 ±46° 内、7 单位以内自动锁定，没有方向输入时锁最近的敌人。自动锁定略优先保留当前目标，避免在相邻敌人之间抖动。目标进入下一次攻击的实际范围时显示明亮光圈和“范围内”；距离不足时显示较暗光圈和“靠近目标”，判定包含前冲、蓄力距离和墙壁。
- 所有角色动画统一每秒 8 帧：待机、跑动、闪避、一个轻击动作、连续穿刺、蓄力三段和施法，共 9 个动作片段，每个 8 个方向，共 432 帧，全部来自同一条管线。粒子、镜头和巨拳飞行不受这个帧率限制。
- 跑动是持剑冲刺：左手向前伸，右手持剑拖在身后，大跨步，每秒约 2.7 步，移速每秒 6.5 单位。闪避约 4.5 单位，再滑行一小段。
- 轻击三段：第一、二下是同一个弓步动作，第三下连续穿刺四次，最后一次最深。三段都可在 0.25 秒后用移动、召唤卡或大招取消；闪避最早在首次命中帧后取消，起手不能取消。第三段期间点下一次攻击，会保留一次衔接，等四次穿刺完成后接出；主动移动取消时清除这次衔接，避免跑开后又自动出招。
- 蓄力刺：蓄力时以正常速度的 35% 移动并跟随瞄准，伤害和距离随时间增长，可用闪避或大招取消。触屏松手释放时保留最后瞄准方向。
- 闪避 0.25 秒，带无敌和残影，先快后慢；2 次充能，每次 1 秒恢复。
- 大招「法天象地」，按顺序播放，不分方向：法象图从左侧滑入并亮相 → 向左退场 → 巨拳从屏幕左上角飞出，砸向 16 单位内敌人最密集的地方（没有敌人时砸主角前方）→ 外圈震荡。地面预警圈在砸下前一直可见，巨拳不受墙阻挡。按键可在攻击中缓存，并可取消收招；未满时按键会抖动提示。
- Token：开局 60，上限 100。每次轻击动作第一次命中 +5，主角亲手击杀 +2，每秒最多涨 12。蓄力刺花 12，不够时不能蓄力。召唤卡、被策反的敌人和替身造成的伤害不回 Token，也不涨觉醒。
- 九张召唤卡（数值在 `src/game/cards.ts`，规则在 `src/game/summons.ts`）：首局带 GLM 和 Kimi，之后开局从卡册里选两张，第三张靠清房奖励补齐，每张都能用 1、2、3 放出。施法第 2 帧才扣费并进入冷却，在那之前闪避或挨打都不花钱；两张卡至少隔 0.35 秒；目标不合法时提示原因且不扣费；进新房间冷却清零，Token 不恢复。扣费的同时战斗定格 0.12 秒，伙伴的半屏立绘从屏幕右侧滑入，约 0.9 秒后滑出（`src/components/CardCutIn.vue`），不挡操作；连放两张时后一张盖住前一张。

- 卡牌升级（文字和数值在 `src/game/cards.ts`，奖励在 `src/game/rewards.ts`，完整表格在设定文档第 4 节）：清完战斗房或踏上 1-8、2-4、3-8 的地台时暂停并三选一，用 1、2、3 或手柄 X、Y、B 选，也能直接点；有“返回”时还能按 4、空格或手柄 A。I 升 II 选分支 A 或 B，III 强化所选分支；选项不够时用补给填满。每个选项是一张卡加一个同宽的文字框，补给（紧急修复、算力补给、扩容）也有自己的卡面。卡牌栏用星级和描边显示等级，暂停菜单列出已选的升级。第一、第二大区最高 II 级，第三大区起才能升到 III 级。
- 伙伴解锁（条目在 `src/game/cards.ts`，存档在 `src/game/progress.ts`）：通关 1-9 解锁 Qwen、MiniMax，通关 2-9 解锁 Seed、GPT、Grok、Gemini，通关 3-9 解救 Claude。解锁写入浏览器的 localStorage，死亡和刷新都不丢，当局立即能从奖励里拿到。奖励三选一只出已解锁的卡，有可拿的卡时固定占一项：有空位直接以 I 级加入，满员时选一张换下。换上的卡接着用被换下那张的冷却，换下的卡保留本局等级，之后还会再出现。Claude 首次在 3-9 解救后永久解锁，后续局可以开局携带，也能从清房奖励和整备编队中选入；已有解锁存档直接生效。再次经过 3-4 和 3-9 时，剧情改为清除圣像中的残留记录。

帧数按每秒 8 帧计，前进单位是世界单位。主角世界尺度为每米 1.5 单位。击杀额外顿帧 0.04 秒，击杀 Boss 至少 0.22 秒。

觉醒开局为 0。主角亲手每造成 10 点伤害 +1，每秒最多涨 3 点；击杀额外 +2，击杀精英或 Boss 额外 +10，这部分不受每秒上限限制。商店地台补满，上限 100。

## 动画管线（X Bot → H3 r2v）

动作由 3D 决定，AI 只负责把人偶画成角色，因此各方向时序一致，朝向、持剑手和位移都能算出来。所有动作从同一个枢纽姿势出发并回到它，所以任意两个动作都能无跳变衔接。

下面的命令都从仓库根目录运行。`tools/`、`art-source/`、`qa/`、`art/` 在仓库根目录，`public/`、`src/` 在 `game/` 下。

```sh

node tools/reference3d/encode-clips.mjs run UL,UR,DL,DR
BLENDER=blender bash tools/reference3d/render-axes.sh "turn" "U,R,D,L"
# 2. 由设定图生成 H3 参考图（需要 art-source 下的四向图和 references/ 下的设定稿）
python tools/make_h3_refs.py
# 3. 本地 ComfyUI 跑 MiniMax H3 r2v 并抠图，已有的条目会跳过。斜向的定位图取自待机条目的静止帧
HUB=idle bash tools/h3-batch.sh v6 "light1 flurry charge" "UL UR DL DR"
HUB=idle bash tools/h3-batch.sh v9 "run" "UL UR DL DR"
# 正上下左右没有设定图：先让角色从相邻斜向转过来，再用转身片段末尾的静止帧作每个动作的定位图
python tools/fit_pose.py turn U --hub light1 --from UR   # R 从 DR、D 从 DL、L 从 UL
node tools/comfy-r2v.mjs turn U --tag v4 --pose hub_turn && python tools/matte_frames.py turn U v4

HUB=turn bash tools/h3-batch.sh v9 "run" "U R D L"
# 后来补的动作用 v10。复活和起身从单膝跪姿开始，定位图分别取死亡和倒地片段末尾的静止帧

npm test
```

需要 Blender 5.2、运行在 8188 端口的 ComfyUI（`COMFY_URL`、`COMFY_ROOT` 可覆盖）、Python 的 numpy / scipy / Pillow、系统 `ffmpeg`。`npm run dev` 与 `npm test` 不依赖这些。动作姿势在 `tools/reference3d/actions.py`，提示词在 `tools/h3-prompts/`，每次生成的参数记录在 `art-source/h3/runs.json`。

大招的两张透明图用 codex 生成，提示词在 `art-source/ult/*.prompt.txt`，压缩后放在 `public/assets/`。

主角的静态图由 `tools/hero_stills.py` 导出到 `art/hero/`：头像和五种对话表情，刺剑的剑柄、护手、剑身分层和 `rapier/rapier.json` 里的挂点，以及 `keypose/` 下八个关键姿势的八向分层和 2048 总表。关键姿势直接从成片切帧，所以和游戏里的动作完全一致。动画里每帧的剑尖位置写在 `hero.json` 每张图集的 `tips` 里，取法和 `anchors` 相同，供从剑尖发出的特效使用。

九张召唤卡也用 codex 生成：提示词是 `art-source/cards/_style.txt` 加各角色的 `<id>.subject.txt`，`tools/card-gen.sh` 出图，签名单独生成透明层后由 `tools/card_signature.py` 合成，人物透明层和技能图标的提示词模板是 `art-source/cards/_figure.txt` 和 `_icon.txt`，头像和缩略图由 `tools/card_exports.py` 导出，技能图标加 `--icons`。定稿在 `art-source/cards/final/`，游戏用的卡面和半屏立绘由 `tools/card_runtime.py` 压缩到 `public/assets/cards/`。三张补给卡的提示词是 `_item.txt` 加 `heal`、`refill`、`cap` 的 `<id>.subject.txt`，不带签名，只有卡面。

界面图同样用 codex 生成，提示词在 `art-source/ui/`：状态、资源和奖励图标，卡背、三级卡框和覆盖层，各界面背景，以及按钮、面板、虚拟摇杆这些组件。`tools/ui_exports.py` 把定稿放进 `art-source/ui/final/`，并把游戏用的 WebP 写到 `public/assets/ui/`。按钮、面板和摇杆后来改成了纯 CSS，这些组件图（`kit-*`）只留在 `art-source/ui/final/`，不再导出给游戏。卡背、锁定覆盖层、I 级卡框、卡册和暂停背景也一样，未解锁的卡直接用角色立绘的剪影。

场景的贴图和远景同样用 codex 生成，提示词在 `art-source/scenes/`。`tools/scene/regions.py` 用基本体列出每个大区的模块，`BLENDER=<blender 路径>` 下运行 `blender -b --factory-startup -noaudio --python tools/scene/build_region.py -- --region port [--room 1-2]` 导出 `public/assets/scenes/<大区>/kit.glb` 和 `modules.json`（每个模块的范围和碰撞、遮挡、拆分标签），`--room` 再按 `level.ts` 把这间房拼出来，用游戏镜头渲染到 `art-source/scenes/rooms/`。`tools/scene/room_plans.py` 画每间房的俯视布局图，`tools/scene/far_layers.py` 导出远景。光照是图集里画的明暗加顶点色的贴地暗角，不需要实时阴影。游戏按大区载入 `kit.glb` 和 `far.webp`，用这些模块把 `level.ts` 的地图拼出来。

技能和敌人的序列帧特效用 codex 生成，提示词在 `art-source/vfx/`，`tools/vfx_exports.py` 导出成 512 的 2×2 序列图 `public/assets/vfx/fx-<ART编号>.webp`。预警圈、脚底投影这类地面贴花由 `tools/vfx_decals.py` 按几何画出，保证形状准确。Web 适配的布局稿由 `tools/ui_mocks.py` 画成 `art/ui/*.svg`，说明在 `../docs/Road_to_AGI_Web适配稿.md`。

## 素材如何接入游戏

- **场景**：`engine.ts` 启动时读入四个大区的 `scenes/<大区>/kit.glb`，房间的地面、墙、实体格、门和部分机关都从模块实例化，背后是该大区的 `far.webp`。游戏不做据点，所以没有潮汐节点的场景。
- **敌人和 Boss**：`tools/pack_enemies.py` 把已有视频的敌人打成动画图集，其余先用设定图做静态贴图，写入 `public/assets/enemies.json`。有新视频后重跑即可替换。Boss 和普通敌人一样是左右两向。过拟合圣像和 Claude 是同一张图，失控、攻击准备、失衡和破印四种状态打在一张图集里。规则在 `enemies.ts` 和 `bosses.ts`，每房的配置在 `encounters.ts`，场上的预警、弹体和地雷由 `hazardView.ts` 来画。
- **主角**：掠潮刺和召唤是规则里的动作。起步、收步、受击、倒地、起身、交互、复活、死亡和致意是 `updateFlourish` 叠在待机和跑动上的表现，不改变手感。
- **特效**：`flipbooks.ts` 的表把事件对应到序列帧，叠在原有的程序图形上，后者仍然表示技能的准确范围。贴花替换了脚底投影、锁定标记、敌人预警和巨拳落点。
- **界面**：按钮和面板都是 `style.css` 里的纯 CSS：直角、深蓝配金，按钮背景是半透明纯色，不加渐变。`public/assets/ui/` 只提供各界面背景、卡框、覆盖层和图标。
- **对话**：`story.ts` 存事件房和 Boss 前后的台词，头像用五种表情和伙伴的立绘。
- **召唤造物**：`tools/creation_exports.py` 从 `art-source/extras` 切图，胶片列车和 Gemini 闪袭是静帧，豆包替身和敌人一样走视频。

还没用到的素材只有各大区的 `modules.json`，是场景工具输出的模块数据，运行时不读。

`art-source/` 不进 git，提示词和成片都只在本机。

十六种敌人的设定图同样用 codex 生成：提示词是 `art-source/enemies/_style.txt`（精英是 `_elite.txt`）加 `<id>.subject.txt`，用 `OUT=art-source/enemies bash tools/card-gen.sh <条目> <主角四向图> <同系列基准图>` 出图。`tools/enemy_contact.py` 把设定图贴到游戏地面色上，和主角放在一起按实际游戏大小检查，`--overview` 导出设计文档里的总览图。敌人身上的标志是六边形线框加短横杠，局部替换的提示词是 `art-source/enemies/_mark.txt`，模型画不准的六张由 `tools/enemy_mark.py` 按量好的位置重画。定稿在 `art-source/enemies/final/`。所有敌人、Boss 和豆包替身都用基本体搭参考模型，模型和动作在 `tools/reference3d/creatures.py`，提示词在 `tools/h3-prompts/enemy.txt` 和 `enemies.json`。`BLENDER=<blender 路径> python tools/enemy_batch.py refs e06` 渲染参考片段并摆好第一张参考图，`python tools/enemy_batch.py takes e06` 跑 r2v 和抠图，已抠好的条目会跳过；`--only`、`--dirs`、`--tag`、`--seed` 用来补拍。种子保持默认的 20261103，换种子常常丢绿幕或把人偶画出来；第二张参考图也要把角色按原大小放在足够的绿底上。`python tools/qa_enemy.py e06 --sheet` 出帧总览并标出贴边和尺寸异常，`python tools/pack_enemies.py` 打包到 `public/assets/enemies/` 和 `enemies.json`，优先用 v3，其次 v2、v1。精英从背后看时第二张参考图只给背面（`sheet_back.png`），不然模型会把它转过来；循环引用弩手站立的动作用 `sheet_standing.png`，不然书架一直是打开的。

已验证的 H3 参数：

| 参数 | 结果 |
| --- | --- |
| 480，20 步，`simple`，124 帧 | 绿幕均匀，贴合参考，约 75 秒一条。当前采用 |
| 896，20 步，`simple`，124 帧 | 绿幕均匀，约 195 秒一条。待机、闪避、施法的斜向是这个档位，缩到运行尺寸后效果够用，没有重做 |

所有成品都用种子 20261103，没有比较过其他种子。

H3 对第一张参考图的依赖比想象的强，这是调参时最容易踩的地方：

- **尺寸和站位跟参考图走**，不跟人偶走，动作幅度小时尤其明显。所以第一张图用 `pose_small_*`：角色缩到画布的 46%，放在绿底上，鞋底对齐人偶。
- **站位差得多时，角色会在开头滑向人偶**。`fit_pose.py <动作> <方向>` 把参考图对齐到该片段的第 0 帧，再用 `--pose small_<动作>` 重生成。
- **小动作会沿用参考图的站姿和持剑方向**。`fit_pose.py <动作> <方向> --hub <条目>` 用已完成条目的静止帧作参考图，再用 `--pose hub_<动作>` 重生成。`--from <方向>` 可以取别的方向的条目。`h3-batch.sh` 设了 `HUB` 就会自动做这两步。
- **定位图的姿势和动作差太多时，有的方向会沿用定位图**。跑步的剑在身后，定位图的剑在身前，参考片段若一开始就是冲刺姿势，8 个方向里有 4 个仍把剑举在身前，只试一个方向看不出来。让片段从枢纽姿势过渡进动作就好了（`actions.py` 的 `run_pose`），取帧都在过渡之后。

改了姿势一定要逐个方向和人偶对比。3D 姿势可以先用 `build_reference.py --keys` 只渲染关键帧，`tools/reference3d/demo_sheet.py` 把它做成 GIF 和帧表来审。

验收时先看 `qa_takes.py` 的高度比（正常约 1.0 到 1.15，跑动因腿部抬起范围更大），再用 `qa_compare.py` 叠图确认。同一种子和输入会得到同一结果，要换结果就改种子或参考图。

`pack-r2v.mjs` 中的 `PLANS` 定义从参考时间线上取哪些帧。每秒 8 帧时一个动作只有几帧，所以取的是姿势最强的峰值，而不是均匀取样。帧数和命中帧必须与 `src/game/simulation.ts` 的 `LIGHT_CHAIN`、`CHARGE`、`ULT` 一致，`validate-art.mjs` 会检查。打包按鞋底位置校正每向的整体偏移，并统一每米像素数，所以各方向和不同动作的角色大小一致。这一步要读参考帧，所以不能只留成品。主角每个动作分两张图集：四个斜向一张，正上下左右一张，因为两组的取景比例不同。还没生成的方向显示相邻的斜向。
